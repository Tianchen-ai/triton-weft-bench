# x86 compiler candidates and references

Select the configured environment from `--plugin-info`; an installation may name
it `triton-weft-x86`. Inspect the implementation's compiler Python, source/artifact
and native SDK. The environment can contain both compiler candidates and independent
reference libraries.

GGML performance runs inspect the CPU translation units in the configured
`compile_commands.json`. The effective optimization level must be `-O2`, `-O3`
or `-Ofast`; a CMake `Release` label alone is insufficient. The command evidence
is saved with the result. Rebuild an incorrectly configured library and replace
only its affected fixed baselines before computing ratios. Check-only invocation
can inspect an unoptimized library without presenting it as a performance reference.

## Triton–Weft candidates

The x86 candidate path is Triton pointer/scalar or typed dense/packed View source → shared
Canonical IR → x86 vector or memref/SCF physical operations → LLVM IR → native shared library.
Use the native adapter from [Triton integration](triton.md), with an explicit
`compile_target` selecting `arch: x86_64`, `march: x86-64-v3` (AVX2) or
`x86-64-v4` (AVX-512), `abi: sysv`, `vlen_bits: 0`. The measurement target continues
to identify the actual machine, CPUs and threads. Load the exported native library;
the LLVM path does not require an exported `kernel.c`.

Optional dot-product features are explicit, such as `x86-64-v3+avxvnni` or
`x86-64-v4+avx512vnni`. Query the product's target/native capabilities before
choosing one; vector width alone does not establish VNNI support. Native JIT
expectations must match discovery, which can include both optional features.
Keep explicit AOT targets distinct from that expectation. The artifact and SDK
enforce the complete feature requirements on the actual executing CPU set.

An x86 source binding may set `backend_options: {"tune_cpu": "sapphirerapids"}`
to select an LLVM scheduling model independently of its ISA target. Inspect the
artifact's `tuning_cpu` metadata and LLVM `tune-cpu` attribute; the declared CPU
features and execution checks must remain unchanged. An empty option uses the
target's default model. Select this explicitly for the measured machine, and
keep candidate timing against the existing matched reference.

For BF16 matrix candidates, an explicit AOT target can select
`x86-64-v4+amx-tile+amx-bf16`. Inspect `available_isa_extensions` separately from
the default native SIMD target. The runtime requests and verifies tile-data
permission on the actual worker; discovery does not establish execution.
`numerical/bfloat_contractions` accepts this target and exercises array tiles,
partial domains, empty reductions and special floating values through the same
artifact. Keep the matched normal oneDNN baseline and its dispatch evidence.

For a configured whole-workload softmax candidate and an existing matching reference:

```sh
python3 "$BENCH_SKILL/scripts/bench.py" --environment triton-weft-x86 op softmax \
  --impl weft --target x86-1t --baseline /path/to/fixed-ggml \
  --output /path/to/runs/softmax
```

Reuse the task's installed compiler Python and matching SDK paths. Development
overlays remain explicit configurations; installed-wheel checks use the installed
package without an overlay. Use `verify --list`, then a selected `--case` or
`--group` for numerical/runtime tasks, or `--prepare-only` for cross-compilation
without device execution. A v3 source/AOT target can execute on a compatible v4
host; Python JIT uses native detection and does not accept an invented ISA override.

Current x86 candidates use the same Triton frontend for pointer/scalar programs,
including `tl.level`, `tl.state` and `tl.stage`, nested levels and same-axis tail
subtiles, outer carry/handoff, zero runtime extent, and ordinary if/for/while.

A vec-dot candidate may declare the complete batch as `W[rows,K]`, `X[K]`,
`Y[rows]`. Bench checks those full port shapes and invokes it once over the same
workload. A one-row artifact retains the native outer row traversal. The result's
`native_call_boundary` identifies the chosen boundary; input data, output checks
and timed work stay the same.

A dequantization candidate can likewise declare `W[rows,K]` and `Y[rows,K]`.
Bench invokes that complete matrix once, retaining the same packed inputs,
codebooks, full output checks and timing contract as the row-entry adapter.
This permits source-controlled row traversal and output streaming hints without
moving any decode work outside the measured invocation.

For a Q4_0 projection consuming GGML's native AMX buffer, a source binding may
declare `persistent_inputs: ["W"]` and
`persistent_providers: {"W": "ggml-amx-q4_0"}`. The provider obtains the normal
GGML-selected packed weight storage before timing and verifies that the selected
buffer is AMX. It checks the declared 16-row cohort and 32-element/18-byte record
ABI. The candidate still quantizes activations inside a complete projection call;
the provider does not run reference mathematics inside the candidate interval.
Shapes for which normal GGML chooses another buffer are rejected.

`amx_q4_0_tile` measures the actual upstream AMX 32-by-32 tile; the separate
`amx_q4_0_decode_tile` measures its VNNI decode traversal, with a positive column
count divisible by 64. The reference calls the actual 64-column specialization
for each packed cohort; it does not substitute a different dot. Both consume already
quantized Q8_0 activations and normal GGML AMX weights, and check every output.
The decode workload binds the actual row ABI `Xq[K]`, `Y[N]`; use the same
single-instance symbol as the model package rather than a separate M1 wrapper.
Their reference is compiled directly from the configured GGML `amx/mmq.cpp`.
Activation quantization and graph dispatch are outside these tile intervals.
Keep their baselines distinct from complete projection and model measurements;
they are diagnostic contracts, not additional entries in an existing fixed suite.
Prefill also accepts an explicit positive column count divisible by 32. The
reference traverses those columns using the same upstream 32-column tile call;
the candidate may consume the complete window through its dynamic View ABI.
Keep the full window dimensions in the comparison. `amx_q4_0_prefill_strided`
and `amx_q4_k_prefill_strided` / `amx_q6_k_prefill_strided` expose `LDC` separately from `N`, pass it through
the typed output stride, and check untouched output padding. Use the model's
actual row distance when diagnosing prefill; contiguous output can have a
different cache behavior. Strided workload ports require a strided artifact ABI.

`amx_q4_k_decode_tile` applies the same complete native decode boundary to Q4_K
weights and Q8_K activations. Its persistent provider is `ggml-amx-q4_k`, with
`AMXQ4_KRows[16]`, 256 elements and 148 packed bytes per record. The normal GGML
buffer expands the original 144-byte record's group scales before timing.
Use its own fixed reference; a Q4_0 tile or an unpacked Q4_K dot is a different
comparison. `ggml.amx/q4_K_decode` consumes this exact storage in llama.cpp.

`amx_q6_k_decode_tile` similarly consumes `AMXQ6_KRows[16]` and `Q8_K`, using
the `ggml-amx-q6_k` provider and the actual GGML VNNI specialization. Its
256-element weight record has 210 bytes. `ggml.amx/q6_K_decode` accepts the
same single-row `W, Xq, Y, N, K` artifact; measure its actual worker window
before adding it to a model package.

`ggml.amx/q4_K_prefill` and `ggml.amx/q6_K_prefill` consume the corresponding
normal AMX weight storage and Q8_K matrices. They accept the same fixed 32-by-32
or dynamic matrix ABI as Q4_0 prefill, without Q4_0's scale workspace. Combine
selected prefill, decode and quantizer roles explicitly. Mixed replaced/native
AMX graphs must pass logits validation: a tile-using artifact releases its state,
and the integration must invalidate GGML's per-worker cached configuration before
the next native AMX node. No extra tile save/restore belongs in every tile call.

The byte contraction probe includes K16 fixed and array snapshots, all four
signedness pairs, tails, empty domains and odd-row K528 validity packets. The
word-byte probe also checks variable I16 scale products with exact wrap before
the I32 contraction. These validate the generic physical lowering independently
of the quantized model kernels.
`amx_mixed_storage` reuses those programs with an array left operand and fixed
right operand. It also writes the source after saving a scaled Value, then checks
full and partial domains against that saved value. Private conditional copies and
direct AMX snapshot reads must retain that mutation boundary.

The `cohort` and `cohort_byte_writes` packed-layout scenarios include smaller
windows inside an interleave cohort, cross-cohort slices, exact neighboring bytes
and inactive rows. The AOT numerical scenario `indexed_packets` covers private
snapshot row reads on v3/v4, including narrow index wrap, partial domains, saved
values after source writes and bounded loop indices. Select these cases in the
existing verification configuration when changing these passes; they are
correctness evidence, not additional operator or model speedup rows.

The native llama.cpp roles `ggml.amx/q4_0_decode` and `ggml.amx/q4_0_prefill`
consume those same weights and the framework's existing quantized activation.
The product validates and loads their typed artifacts; Bench neither recompiles
generated code on deployment nor disables AMX/repack. `amx` and `amx_observed` in
the measured-window counters are separate from generic vec-dot and RISC-V IME
counts. A single-row output projection can run during a prefill phase, so the
role name alone does not identify which measurement window contains its calls.
Dynamic prefill artifacts receive adjacent output-column tiles already assigned
to one worker and input-row block in a single native call. Fixed 32-by-32
artifacts retain their tile calls. Consequently a call counter counts native
invocations, not a fixed number of columns; numerical checks and the measured
window still determine whether the complete model computation was replaced.
The `ggml.from_float/q8_0` and `ggml.from_float/q8_K` bindings also cover the
integrated AMX preparation call sites. Unbound calls retain the exact upstream
function, including AMX's Q8_K reference quantizer. Require numerical validation
and measured-window quantizer hits before attributing a model gain to this route.
For a same-binary zero-hit control, set that implementation's
`validation_expect_replacement: false`. Its numerical check must observe zero
replacement calls; ordinary candidate packages still require a hit. This permits
checking control logits without treating an unobserved candidate as successful.
Local Values support scalar element updates, matrix row extraction with omitted
trailing axes, and standard row/column gather. Configured probes also cover SIMD
arithmetic, reductions, ordinary dot, scan/atomics and JIT/AOT.
The array packet numerical probe reuses one compiled kernel across contiguous,
gapped, transposed and read-only broadcast inputs, and checks untouched output
holes. Runtime stride checks must preserve each View's actual storage relation.
It also checks scalar reduction results on empty and nonempty dynamic domains;
an inactive result must not overwrite the caller's output sentinel.
The same probe checks numerical producer forwarding across a source write: a
saved input snapshot and a multi-consumer intermediate must keep their original
values. An integer chain checks narrowing, widening and modular reduction before
and after forwarding. A retained stage checks its rounded F32 product before a
body subtraction and power-of-two scaling, exposing illegal cross-birth FMA even
when physical region flattening puts the traversals in one block. Empty and
partial stage domains reuse the same compiled program and retain output guards.
Physical fusion evidence is saved separately from numerical
and timing results; removing arrays alone does not establish a speedup.
The array probe also keeps 16- and 256-element numeric snapshots across a dynamic
reduction, then mutates the source and consumes the saved snapshot. These cases
exercise surrounding residency without changing the reduction's author program.
Inspect emitted candidate/resource metadata separately: a numerical pass does
not prove that a particular schedule was selected or that register allocation is
spill-free. Use the existing v4 JIT and v3 AOT entries for this same probe.
Uniform validity storage elimination must retain nonuniform Level tails, inactive
empty reductions, snapshot lifetimes and runtime layout changes. The same probe
saves its removed-validity-array count when the compiler reports it, alongside
the numerical and source-IR evidence rather than as a correctness assertion.
The array probe also projects rectangular fixed tiles from runtime-sized saved
Values after a source write. It checks both-axis tails, empty domains, output
gaps, BF16 payloads and byte-addressed I1/U4/I4 arrays. Typed helpers use renamed
dimension symbols and mixed static/runtime View extents; specialization must not
lose a helper's dimension or bind it to a same-spelled caller symbol.

Typed dense Views also use this frontend and native SDK. The configured dense View
cases cover CPU Tensor eager calls, dynamic ABI shape/strides/storage offset,
read-only zero-stride inputs, 2D Level tails and same-axis subtiles, subview/extent,
declared alias rules, and export/load with changed runtime layouts. Runtime-sized and
large fixed local Values use array storage in the same lowering, including whole-row
normalization, contraction, multi-value loop carries and retained dense/encoded stages.
Preserve the author's shape and tile when checking these paths; a smaller fixed-tile
variant is a different source case. For source-auto, Config and cache/AOT semantics,
see [source parameters](triton.md#source-parameters-and-triton-config).

The alias scenario also saves a View snapshot, overwrites its backing input, and
broadcasts the saved values across SIMD columns. It checks empty, partial and
multiple tiles, input guards and strided output padding. This covers packet
broadcast load selection without allowing reads to move across the source write.

View tail validity must survive reductions and combinations with pointer operations.
The tail case includes negative maximum/first argmax, sum, positive minimum, and
an integer View whose values determine pointer atomic addresses. It checks that
only valid elements contribute effects. Do not replace a View tail with ordinary
zero-filled pointer inputs, or add a source mask that hides the compiler behavior
under investigation. Reuse these configured cases instead of building another runner.

Level state/stage initializers capture SSA values visible before entering that
Level, plus its point. A body carry is not automatically the current value in a
birth region. For pointer-only lifetime checks, explicit fixed-address loads and
body memory updates can distinguish birth frequency and staged reuse. Use only
the public syntax; do not invent a point offset property or fabricate Canonical IR.

Helper work uses the same public sources and Canonical helper regions on x86 and
RVV. Select the configured checks for noinline calls, early returns from for/while
and Level instances, fixed shaped returns, and strided View descriptors. A return
exits its helper while preserving completed effects; the caller continues after
the call. Multi-block inputs distinguish a return from finishing one Level instance.
Passing an outer point and selected View into a helper must preserve parent origins,
tails and state/stage births in nested `level.subtiles`.
Use the task's passed compiler environment for the required combination. Installed
wheel results are recorded separately from development-overlay results.

The helper probes retain `weftir`, `x86ir` and `llir` and inspect emitted noinline
definitions and calls. Saved disassembly of the produced shared library can confirm
the actual native call boundary. An ordinary inline helper may disappear from the
native symbol table; that is expected. Neither observation is a timing result.

Grouped arithmetic uses the closed `tl.mac_pairs/mac_groups` operations with
explicit `into`, widening by operand signedness and the declared accumulator
overflow. Free axes follow the shared Canonical contract; the group need not be
two or four. `tl.sum_pairs` maps to `fold2` and returns i32. The configured numerical
cases include mixed signed/unsigned integer wrap, f32/group-three and partial groups.
Inactive terms contribute zero; a grouped result is active when any term is valid.
The grouped arithmetic probe includes full-range U8×I8 and I8×I8 four-product
groups, U8×U8, -128, independent free axes, and partial/empty domains. These
check exact integer results without assuming the values of a particular codebook.
Invocation packing workspaces remain populated inside the native call; the
native adapter allocates declared `workspaces` from the exported typed ABI.
An interleaved encoded workspace requires a two-dimensional shape, complete
records and complete row cohorts. The adapter checks its allocation size against
the artifact's exported layout helper. Allocation occurs before timing; scale
widening or other population performed by the source remains inside the timed
invocation. In particular, `q4_0_prefill_scales` declares `Scales` with a 32-row
cohort and can reuse exact F32 activation scales across the assigned output
columns. Select that artifact explicitly for its matching native/model role.

`tl.lookup(table, indices, bounds="in_bounds")` requires unsigned/index indices
within the active table domain. It has no public mask/fill or alternate OOB policy.
A local table retains its original load snapshot across later backing-storage writes;
passing a View directly admits its contents at that call. Internal View tail lanes
remain inactive. The configured `numerical/lookup` probe covers both 16- and
128-entry tables using the same snapshot, scalar and inactive-tail/counts checks;
select this correctness probe when changing large-table lookup lowering.
It includes an 8192-entry saved table, direct lookup into large strided 2D Views,
a single-consumer snapshot separated from lookup by a table write, and narrow
index wrap inside otherwise contiguous codebook rows. These checks distinguish
legal sparse reads from moving a saved read across effects. Wide I8/F32 values
also retain their snapshots through dynamic scalar projections after a write.
Record-row cases exercise bounded index arithmetic, explicit narrowing across a
row, contiguous and strided tables, empty domains and partial output tiles.
The existing inner-control Level case reuses an ordinary loop induction name
after initialization, checking that a completed loop does not become Level state.
The same lookup probe supports explicit v3/v4 AOT and small byte/F32 tables
with non-power-of-two lengths, multiple output packets and inactive tails. It
checks exact snapshot bits across a table write, including signed zero, infinity
and NaN payloads for movement. This is distinct from arithmetic NaN policies.
The array packet probe includes BF16 snapshots returned by a noinline helper,
strided storage, and explicit RNE/RTZ narrowing boundaries. It exercises actual
conversion and ownership paths; an exported library must load without conversion
runtime dependencies. Inspect `compilation.local_storage` separately for reserved
slots and policy budgets, which exclude LLVM's later register spills.
The scalar-validity case follows an extracted tail scalar through
casts, arithmetic, helper arguments/returns and caller for/while/if carries, then
checks both stores and atomic counts. Reuse these cases when changing scalar masks.

Packed Encoding checks cover field/record storage, signed small fields, layered/joined
layouts, byte/bit order, domain-selected fields and stage snapshots. Existing GGML
source cases exercise quantization, dequantization, dot and complete projection.
BF16 storage checks retain stored bits before widening; dynamic rounding has a separate
fenv probe. Use the configured original sources and their oracles for the affected path.
The `extrema_and_half` numerical scenario checks odd fixed tiles, empty/tail
domains, all-NaN extrema, mixed signed zeros and literal zero bounds, plus every
FP16 bit pattern through scalar widening. The `byte_sum` scenario checks signed
and unsigned byte sums, masked padding and modular I16 overflow. Both support
native JIT and explicit AOT targets. The array extrema oracle reduces actual
nonempty values without an extra infinity seed, preserving an all-NaN result.
The explicit-AOT `byte_planes` scenario checks every byte value through unsigned
1-, 2- and 4-bit field extraction/placement, equal or unequal neighboring shifts,
empty domains and SIMD tails. Run it on the affected V3/V4 target when changing
subbyte carrier selection; it does not produce a performance ratio.

An IME-named packed workload describes its data layout, not an ISA requirement for
every implementation. A Triton native artifact uses the SDK's actual ISA and worker
permission checks. The GGML/legacy IME implementation still requires the configured
SpacemiT hardware; do not pretend an x86 target has that extension.
AMX candidate lowering and Inductor support need their own evidence.

For target-width array lowering, the configured numerical `array_packets`
scenario covers runtime lengths around vector boundaries and 4096 elements,
row and column reductions, boolean storage, F64, I32 wrap, empty domains,
NaN/Inf policies and large masked tails. Native JIT follows actual discovery.
To validate an explicit lower ISA such as v3 on a v4 host, use this scenario's
`execution_mode: "aot"` with its `compile_target`; do not pretend native JIT
discovered a different CPU. AOT compiles through the same ASTSource/backend and
runs the same artifact across runtime shapes.

The `array_contractions` numerical scenario uses the same public frontend and
native AOT path for v3/v4. It covers runtime matrix dimensions, empty reductions,
integer wrap, gapped/transposed/broadcast Views, shared batches and multiple
reduction axes. It also composes standard `tl.sum` with named-axis scales, checks
signed/unsigned subbyte snapshots across external writes, and exercises narrow
pointer-index wrap with masked loads. Inspect `packet_candidates` separately
from numerical results; packet selection does not establish matmul performance.

Another machine's CPU is a separate Bench target and needs its own reference.
Use the existing SSH executor, native SDK checks and worker; keep host paths and
CPU/NUMA placement in external configuration. `register_file` describes target
capacity; `compilation.array_schedules` describes selected physical packets and
estimates, not measured register allocation. Reuse each machine's matched
baseline, and keep width comparisons distinct from source-program changes.
GGML/oneDNN AMX performance belongs to the reference library. An
operator improvement is not evidence of x86 llama.cpp acceleration; replacement,
hit counts and stage timing need their own actual run.

## Invocation scratch

For a source that explicitly packs invocation panels, configure the Triton native
adapter with `"workspaces": ["Scratch", "Activation"]` (the actual ABI argument
names). Bench derives their dense shapes and storage types from the artifact,
allocates before timing and poisons the initial contents. The kernel must fill
the scratch it uses during every timed invocation. This does not turn invocation
packing into persistent preparation. `invocation_workspaces` records the buffers
and timing boundaries. Storage is aligned to the least common multiple of 64
bytes, the ABI alignment and its element width; the ABI's required alignment
remains separately recorded. Dense and base-record scratch use the artifact's shape,
record size and alignment; incomplete records, persistent interleaved scratch,
aliased mappings and strided scratch are rejected. Storage is poisoned before
validation, and the candidate must populate every value it reads inside the
invocation. Reuse the normal operator worker and oracle.

Output-only `Y` may be readwrite in the kernel when it initializes its partial
sum before accumulation. Bench poisons that initial output before checking;
the kernel's initialization remains timed. An inout workload retains caller state.

For a projection whose author declares a persistent interleaved weight View,
set `persistent_inputs: ["W"]`. The native adapter requires the artifact's
`artifact_pack` base Encoding and exported size/pack symbols, validates the
complete record/cohort shape and packs the original workload weights before
timing. It calls the candidate's native builder; it does not reimplement the
layout or change the input oracle. `persistent_inputs` records the resulting
layout, storage size and preparation boundary. Only read-only projection weights
currently have this preparation contract. Activation quantization, invocation
scratch and the complete projection remain timed. Reuse the same normal GGML
model-default weight baseline when the existing comparison contract matches.
Persistent output storage is explicitly aligned to both a 64-byte allocation
boundary and the artifact's required alignment. The recorded allocation alignment
is a caller preparation policy, not a stronger promise added to the kernel ABI.
Allocation padding stays outside the logical buffer and the timed invocation.

The packed `cohort` numerical case independently checks byte ordering against
the exported builder, complete cohort loads and slices crossing a cohort.
`byte_contractions` covers mixed/signed/full-unsigned inputs, extreme values,
runtime output/reduction tails and empty domains in JIT and explicit AOT.
The natural, layered/joined and byte-order probes also reshape encoded snapshots
whose byte spans differ from their logical element counts. They check exact
record bytes, field values, whole-record permutations and empty/partial domains.

## Installed default toolchain

The x86 wheel bundles Clang23 and OpenMP23. To check the default installed path,
the configured `pointer_jit_aot` case sets `request.default_toolchain: true`.
It omits the toolchain argument and checks cold/warm JIT, export and reload, the
package's compiler path, exported `runtime_files` containing libomp, and the loaded
OpenMP library. This is a separate check from explicit-toolchain or Level results.
JIT may load a cache copy declared in `metadata.runtime_files`. Accept only the
listed dependency paths whose file contents equal the installed provider, along
with the corresponding exported copy; an entire cache directory is not an allowlist.
The probe saves the loaded paths and copy comparisons before reporting a failure.

Select the installed Python without an overlay and use
`verification.runtime.unset_environment` to clear `TRITON_WEFT_CC`, `PYTHONPATH`
and external compiler include/library path overrides in both provenance discovery
and execution. Preserve the task's prepared default-toolchain configuration; do not
substitute the development overlay or shared OpenMP to make this check pass.

Source compilation also inherits the CLI process environment: clear its external
compiler/library overrides for an installed check. Author-only import roots needed
by unchanged kernels (for example formats/functions/kernels) may remain explicit;
they must not select a development compiler or runtime. The native Bench worker's
C/C++ toolchain is distinct from the candidate's `toolchain: {}`.

When the local configuration includes the installation entry, select it directly:

```sh
python3 "$BENCH_SKILL/scripts/bench.py" --environment triton-weft-x86 verify \
  --target x86-1t --case installation/pointer_jit_aot_default_toolchain \
  --output /path/to/runs/default-toolchain
```

## Reference libraries and normal models

```sh
python3 "$BENCH_SKILL/scripts/bench.py" --environment triton-weft-x86 --plugin-info
python3 "$BENCH_SKILL/scripts/bench.py" --environment triton-weft-x86 environment --target x86-1t
python3 "$BENCH_SKILL/scripts/bench.py" --environment triton-weft-x86 op q4_k_dot --impl ggml --target x86-1t
python3 "$BENCH_SKILL/scripts/bench.py" --environment triton-weft-x86 op gemm_f32 --impl openblas,onednn --target x86-8t
python3 "$BENCH_SKILL/scripts/bench.py" --environment triton-weft-x86 op gemm_bf16_f32 --impl onednn --target x86-8t
python3 "$BENCH_SKILL/scripts/bench.py" --environment triton-weft-x86 e2e llama2-7b-q4_0 --impl normal --target x86-8t --phase both
```

Use GGML for its native quantized/operator path and normal llama.cpp for model
baselines. OpenBLAS supplies F32 SGEMM; oneDNN supplies strict F32, BF16→F32 and
S8→S32 matmul. These are actual library references, never substitute Weft
candidates. Reference-only commands require no Weft compiler. Preserve existing
single-instance/grid/host-call scopes when comparing a configured candidate.

The oneDNN path uses plain logical strides; primitive creation, input allocation
and scratchpad allocation precede timing, while execute+wait includes internal
packing. BF16 oracles use stored BF16 values; S8 checks use full signed-range
inputs and integer accumulation. Small typed matmuls check all outputs, larger
ones report sampled-64 checking. GGML dequantization can report
`library-reference-self-consistency`; do not call that independent validation.

An explicit Q8_K storage contract distinguishes first-absolute-max RTNE from the
legacy RVV extrema rule. Preserve the configured contract when reusing a result.
Do not change data or tolerances to hide a mismatch.

Complete model projection can select `ggml.projection_weights=model-default`:
normal CPU extra-buffer selection and persistent weight repacking happen before
timing, while activation quantization and graph execution remain inside. The
scope ends in `/persistent-model-default-weights`. A candidate's original scope is
retained; `projection_boundary` records its prepared W/X buffers and timed call.
Comparisons accept the base/suffixed pair only with both sides' complete-operator
evidence, recorded in `comparison_basis`. Existing GGML dispatch evidence can be
reused without rewriting or remeasuring the fixed reference. Other shape, input,
precision, cache and execution fields must still match; leaf/grid scopes remain distinct.
The recorded GGML weight buffer name is storage evidence; AMX-buffer decode can
use VNNI, so it is not by itself an AMX-instruction execution claim.
Likewise, a plain `CPU` weight buffer can enter GGML's tiled matrix path with
invocation packing and VNNI microtiles. Inspect the matched build and actual
dispatch before treating a projection as repeated calls to its vec-dot leaf.
Keep dispatch debugging outside the operator measurement interval.

`f16_projection_decode/prefill` explicitly round activation X to F16 before the
projection. `f16_f32_projection_decode/prefill` instead preserve original F32 X,
with stored F16 W and W/X/Y candidate ABI (no Xh/Xq scratch). The mixed oracle
uses decoded W × original X, with existing tolerances, and the full-call scope is
`projection-preserves-f32-activation`. Choose the case matching the author's math;
these two contracts and their baselines are not interchangeable.

For the mixed GGML reference, keep normal model-default selection. Bench inspects
the selected build's known F16/F32 source path and records the actual buffer,
compute symbol and DSO. The recognized AMX-buffer F16 path uses AVX-512 F32
accumulation. Unrecognized source reports unsupported; an incompatible selected
dispatch reports `contract_mismatch` before sampling. Do not change the oracle or
disable library optimizations to force agreement.

`environment` observes CPUID, OS xstate permission, affinity and NUMA. It does not
execute AMX. Use `reference_dispatch` from a successful run for the actual library
entry/DSO, OpenBLAS core or oneDNN primitive. `amx_executed=true` requires actual
AMX primitive execution and an accepted oracle; CPU flags or tile permission
alone are insufficient. Model environment observations use a separate process
under the same deployment settings.

Direct dot/rows and Norm/RoPE/softmax leaves are single-thread boundaries. A complete
GEMM/projection using native `entry=single` is also one thread. Multithread references
use their actual library thread settings; candidates need an explicit grid/framework
entry, not just an 8/52-thread target. Preserve single/grid/host-call timing scopes.
Use the configured physical CPU set and NUMA command; machine addresses, private
paths and thread selections remain in external configuration.

Normal-only `e2e --validate` captures a fixed prompt/token/logit reference, labeled
`reference-logits-captured`, without self-comparison. To add that reference to
